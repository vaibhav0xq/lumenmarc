# Deploying LumenMarc on Netlify

LumenMarc deploys to Netlify as **one project**: the Vite front end is served as static files and the Express API runs as a single Netlify Function behind `/api/*`. It is the same code as the Vercel deployment (`docs/DEPLOY_VERCEL.md`); only the wrapper differs, because Netlify functions receive a Lambda-style event instead of Node's `(req, res)` pair. `serverless-http` bridges that in `artifacts/api-server/src/netlify.ts`.

The repository ships a `netlify.toml` and a build script (`scripts/netlify-build.mjs`), so the Netlify dashboard needs almost no configuration.

## 1. Settings

Import `github.com/vaibhav0xq/lumenmarc` (Add new project → Import an existing project → GitHub) or deploy with the CLI (section 5). Everything below is read from `netlify.toml`; the values are listed so they can be checked against the UI.

| Setting | Value |
| --- | --- |
| Base directory | repository root (leave empty) |
| Build command | `pnpm run build:netlify` |
| Publish directory | `artifacts/lumenmarc/dist/public` |
| Functions directory | `netlify/functions` (generated by the build, one function: `api`) |
| Functions bundler | esbuild (`node_bundler = "esbuild"`) |
| Node version | 22 (`NODE_VERSION = "22"` in `netlify.toml`; the functions runtime follows the build's Node major, so the function runs on `nodejs22.x`) |
| Package manager | pnpm 10.26.1 via Corepack, from the `packageManager` field; Netlify runs `pnpm install` because `pnpm-lock.yaml` exists |
| Redirects | `/api/*` → `/.netlify/functions/api/:splat` (200, forced) and `/*` → `/index.html` (200, SPA fallback) |
| Headers | `/assets/*` → `Cache-Control: public, max-age=31536000, immutable` |

Do not set `NODE_ENV` for the build: Netlify leaves it unset, which is what installs the devDependencies (Vite, esbuild, TypeScript) the build needs. The function bundle fixes `NODE_ENV=production` at build time.

## 2. Environment variables

All of them are optional; the deployment works with none of them set. Add them under Project configuration → Environment variables (scope: Functions and Builds is fine). Variables in `netlify.toml` would only be visible at build time, so runtime values must be set in the UI, CLI or API.

| Variable | Purpose | Recommended for production? |
| --- | --- | --- |
| `BASE_RPC_URL` | Keyed Base mainnet RPC (Alchemy, QuickNode, Infura, Coinbase Developer Platform). Without it the public Base RPCs are used with fallbacks, and an occasional refresh can fail on rate limits (the app keeps its last snapshot and says so). On Netlify this matters more than elsewhere: synchronous functions have a 10 second limit on the Free plan, and a cold snapshot over slow public RPCs eats into it. | **Yes** |
| `DATABASE_URL` | Postgres connection string (Neon works well; use the **pooled** connection string, the host containing `-pooler`). Backs the premium **history** series only. Without it every other feature works and the history endpoints answer `history_disabled`; the UI shows that message instead of an empty chart. | Yes, for the demo |
| `PUBLIC_APP_URL` | Canonical public origin, e.g. `https://lumenmarc.netlify.app`, used in share text and embed snippets. Falls back to the request host. | Optional |
| `CRON_SECRET` | Enables *forced* refreshes on `GET /api/cron/snapshot` for callers presenting `Authorization: Bearer <CRON_SECRET>`. Without it the endpoint only refreshes when the snapshot is stale, like any read endpoint. | With a scheduler |
| `LOG_LEVEL` | pino level (`info` default). | Optional |

Nothing else is read from the environment.

### Database schema

Apply the single table once (from your machine, with the same database; the direct, non-pooled URL is fine here):

```bash
DATABASE_URL=postgres://... pnpm --filter @workspace/db run push
```

## 3. How the Netlify deployment behaves

- **Snapshots are computed on demand.** A function instance recomputes the market snapshot when its in-memory copy is older than 45 s (one Base multicall pass + DexScreener, about 0.5 to 3 s). Concurrent requests share one computation.
- **CDN caching absorbs traffic.** Read endpoints send `Cache-Control: public, max-age=15, s-maxage=30, stale-while-revalidate=60`, which Netlify's CDN honours for function responses, so a burst of visitors does not become a burst of RPC calls.
- **History is traffic-driven unless you schedule refreshes.** Rows are written at most once every 50 s *when a snapshot is computed*. If nobody visits, nothing is recorded. To keep the 24-hour chart continuous, point an external pinger (cron-job.org, UptimeRobot) at `https://<your-domain>/api/cron/snapshot` with the header `Authorization: Bearer <CRON_SECRET>`. Netlify's own scheduled functions would need a second function; the pinger keeps the deployment identical to the Vercel one.
- **Free plan budget.** Netlify's Free plan is credit based (300 credits per month for the whole team, shared by every project on it): a production deploy costs 15 credits, compute is billed per GB-hour of function time and web requests per 10,000. A pinger every minute is about 43,000 function runs a month and would use a large share of that budget; every 5 minutes is comfortable. When the team's credits run out, all its projects pause until the next cycle.
- **Nothing is faked.** If Base RPC and DexScreener both fail before the first snapshot on a cold instance, the API answers `503 snapshot_unavailable` and the UI says so. After a first success, failures keep the previous block-stamped snapshot and surface a warning.

## 4. Smoke test after the first deploy

Replace `APP` with your deployment URL:

- `APP/` loads the instrument with 13 rows and the market-session indicator
- `APP/api/healthz` → `{"status":"ok"}`
- `APP/api/overview`, `APP/api/stocks/NVDAc` (priced), `APP/api/stocks/TSLAc` (`priceUsd: null`, `deviationState: "unpriced"`), `APP/api/check?q=TSLAc`
- `APP/readings?t=TSLAc`, `APP/s/NVDAc`, `APP/check?q=TSLAc`, `APP/portfolio/jesse.base.eth`, `APP/embed/NVDAc`, `APP/about`
- `APP/api/cron/snapshot` → `{"ok":true,"mode":"on-demand",...}` (`"forced":true` only with the bearer header)
- With `DATABASE_URL` set: reload `APP/s/NVDAc` after two to three minutes, the premium-history trace should show points once rows exist

## 5. Reproducing the build locally and deploying with the CLI

```bash
pnpm install
pnpm run build:netlify                    # artifacts/lumenmarc/dist/public + netlify/functions/api/api.js
npx netlify-cli serve                     # http://localhost:8888, static files + the function + the redirects from netlify.toml
npx netlify-cli deploy --prod --dir artifacts/lumenmarc/dist/public --functions netlify/functions --site <site-id>
```

The CLI deploy uploads the built site and the function as they are (no build on Netlify), reads the redirects and headers from `netlify.toml` and needs `NETLIFY_AUTH_TOKEN` in the environment (User settings → Applications → Personal access tokens). A Git-connected project rebuilds on every push to `main` instead.

## 6. Custom domain

Project configuration → Domain management → add the domain, then set `PUBLIC_APP_URL` to it and redeploy so embeds and share links use the canonical host.
